# S3.6 — Embedding Evaluation

## Purpose

S3.6 verifies the geometry of the learned embedding space:

- images of the **same product** should have smaller distance;
- images of **different products** should have larger distance.

This task is intentionally independent from S3.4/S3.5 training pair CSVs and from the S2.8 retrieval ranking evaluation.

## Evaluation protocol

Dataset 1 `train` is used because it contains repeated images for the same product. The `valid` and `test` splits contain one image per product group in the current dataset construction, so they cannot provide a sufficiently large same-product pair population.

The evaluator:

1. Loads the validated Dataset 1 manifest.
2. Selects one split (`train` by default).
3. Builds all unordered positive pairs within the same `group_id`.
4. Samples an equal number of independent negative pairs from different product groups using a deterministic seed.
5. Does not reuse S1.10/S3.5 training pair CSVs.
6. Applies the production preprocessing pipeline without augmentation.
7. Loads each Siamese `best.pt` checkpoint with the exact `SiameseNetwork` architecture.
8. Extracts normalized embeddings.
9. Measures cosine distance as the primary metric and Euclidean distance as a secondary diagnostic.
10. Reports distance distributions, separation, ROC-AUC, PR-AUC, best threshold, EER, and leave-one-image-out nearest-neighbor accuracy.

## Pair semantics

Evaluation labels are independent of the S1.10 training label convention:

- `1` = same product (`group_id_1 == group_id_2`)
- `0` = different product (`group_id_1 != group_id_2`)

Negative pairs are additionally classified as `same_category` or `cross_category` for diagnostics. Category is never used to define product identity.

## Models

The default CLI compares:

- S3.4 Hybrid 50/50: `experiments/siamese/checkpoints/best.pt`
- S3.5 Random: `experiments/siamese/sampling_experiments/random/checkpoints/best.pt`
- S3.5 Same Category: `experiments/siamese/sampling_experiments/same_category/checkpoints/best.pt`
- S3.5 Different Category: `experiments/siamese/sampling_experiments/cross_category/checkpoints/best.pt`

## Running

From repository root:

```bash
python scripts/evaluate_embedding.py --dataset-root "E:\Programming Project\Visual Recognition Engine\dataset\ai-tool-pool-jewelry-vision"
```

CPU execution can be forced with:

```bash
python scripts/evaluate_embedding.py --dataset-root "E:\Programming Project\Visual Recognition Engine\dataset\ai-tool-pool-jewelry-vision" --device cpu
```

Custom checkpoints can be supplied with the four checkpoint arguments exposed by the CLI.

## Interpretation

A stronger embedding should generally show:

- lower same-product mean/median cosine distance;
- higher different-product mean/median cosine distance;
- larger positive-vs-negative separation;
- higher ROC-AUC and PR-AUC;
- lower EER;
- higher leave-one-image-out nearest-neighbor same-product accuracy.

S3.6 does **not** replace S2.8. S2.8 answers whether a product is retrieved in Top-K under the product-level retrieval protocol. S3.6 answers whether the embedding space itself separates product identity. Final retrieval conclusions should use both evaluations.

## Reproducibility policy

Policy: `s3.6-independent-embedding-geometry-v1`

Default seed: `2026`

Default negative ratio: `1.0`

Default split: `train`

Evaluation is deterministic at pair construction level and uses no image augmentation.
