# S4.3 — Gallery Loading

## Objective

Load the materialized S3.7 retrieval gallery into memory so S4.1 can perform runtime product search without rebuilding embeddings for every request.

## Runtime contract

```text
S3.7 persisted artifacts
        │
        ├── gallery_embeddings.pt
        └── gallery_metadata.json
                │
                ▼
        GalleryLoader
                │
                ├── validate files
                ├── load embeddings
                ├── load metadata
                ├── validate alignment
                ├── validate 128-D contract
                ├── validate unique image IDs
                └── validate L2 normalization
                │
                ▼
        RuntimeGallery
          ├── Gallery (in memory)
          └── SimilaritySearchEngine
```

The selected MVP model is `s3.5_random`, matching the S3.11/S3.12 retrieval decision. The loader is configuration-driven so another model/gallery can be selected without changing S4.1.

## Default paths

```text
experiments/retrieval/siamese/s3.5_random/gallery_embeddings.pt
experiments/retrieval/siamese/s3.5_random/gallery_metadata.json
```

The `.pt` artifact is intentionally ignored by Git because model/embedding binaries are excluded by the repository `.gitignore`. The runtime therefore expects the locally generated S3.7 artifact to exist on the machine running the MVP.

## Validation

S4.3 rejects:

- missing embedding file
- missing metadata file
- empty gallery
- embedding/metadata row mismatch
- unexpected embedding dimension (default 128)
- non-finite embeddings
- empty product/category/image identity fields
- duplicate image IDs
- non-unit embeddings when the normalization policy is enabled

The default unit-norm validation is consistent with the current Siamese embedding contract and the cosine-similarity retrieval design.

## In-memory support

`GalleryLoader.from_gallery()` accepts an already materialized `Gallery`. This allows tests, notebooks, future database-backed galleries, or an API startup cache to inject the gallery without depending on filesystem paths.

## S4.1 integration boundary

`RuntimeGallery.search_engine` is directly compatible with `InferencePipeline`:

```python
runtime_gallery = GalleryLoader().load()
pipeline = InferencePipeline(embedder, runtime_gallery.search_engine)
```

S4.3 does not load the model checkpoint. Model loading remains a separate concern so the selected embedding model and selected gallery remain explicit runtime dependencies.

## Current S3.7 artifact

The repository contains the metadata/report artifacts for all four S3.7 experiments, including `s3.5_random`; the binary `gallery_embeddings.pt` files are ignored by Git. The S3.7 summary recorded aligned 128-D galleries for the four experiments. The runtime default selects `s3.5_random` because S3.12 selected it based on retrieval performance.

Policy: `s4.3-runtime-gallery-loading-v1`
