# S4.8 Rotation Robustness Diagnostic

## Purpose

The S4.8 end-to-end test currently has one failed scenario: a 12-degree rotated Ring query is returned as `pendant`. Before changing the model, this diagnostic separates a model robustness problem from a test-transformation problem.

## Method

The diagnostic uses the same Ring test image that passed the normal S4.8 Ring scenario and sends several controlled variants through the real running API:

| Variant | Rotation | Resampling | `expand` | Purpose |
|---|---:|---|---|---|
| `baseline_0deg` | 0° | BILINEAR | false | Reference result |
| `train_like_plus5deg` | +5° | BILINEAR | false | Within training rotation range |
| `train_like_plus10deg` | +10° | BILINEAR | false | Training rotation boundary |
| `controlled_plus12deg` | +12° | BILINEAR | false | Slightly outside training range |
| `controlled_minus12deg` | -12° | BILINEAR | false | Directional check |
| `s48_original_plus12deg` | +12° | BICUBIC | true | Exact original S4.8 construction |

The training augmentation implementation uses small in-plane rotations up to 10 degrees, BILINEAR resampling, and `expand=False`. The original S4.8 scenario instead used BICUBIC and `expand=True`. The diagnostic intentionally compares both constructions rather than silently changing the existing S4.8 test.

## What is measured

For every variant the report records:

- returned category;
- Top-K products and similarity scores;
- first Ring product rank inside Top-K, using gallery metadata rather than product-ID naming conventions;
- request latency;
- transformation parameters.

Similarity is the existing display score. It is not interpreted as probability or calibrated confidence.

## Interpretation

The script writes `experiments/e2e/s4.8_rotation_diagnostic.json` and emits one of three interpretations:

- `strong_evidence_test_construction_issue`: the training-like +5° and +10° variants return Ring while the original S4.8 construction does not.
- `evidence_model_rotation_robustness_issue`: at least one training-like rotation fails to return Ring.
- `inconclusive_requires_further_rotation_analysis`: the controlled outcomes do not cleanly distinguish the two hypotheses.

These labels are diagnostic evidence, not statistical proof. A model change must not be made solely from the original S4.8 failure.

## Execution

Start the real API with the same S3.5 Random checkpoint used by S4.8, then run:

```powershell
python scripts/run_rotation_diagnostic.py
```

Or specify the exact Ring image and output path:

```powershell
python scripts/run_rotation_diagnostic.py --ring-image "E:\Programming Project\Visual Recognition Engine\dataset\ai-tool-pool-jewelry-vision\test\Ring\ring_161_jpg.rf.ad1f0fa2a46757f02686ee9abd024646.jpg"
```

The API must already be running at `http://127.0.0.1:8000` unless `--base-url` is supplied.

## Scope boundary

This is a diagnostic experiment only. It does not retrain the model, modify the gallery, change preprocessing, alter the API contract, or replace S3.11 quantitative retrieval evaluation. The original S4.8 result remains recorded unchanged for traceability.
