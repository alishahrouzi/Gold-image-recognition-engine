# S4.6 — Error Handling

## Purpose

Define a stable public error boundary for the MVP search API. Internal model, gallery, preprocessing, and runtime exceptions must not leak implementation details to API clients.

## Public error schema

Expected API failures use:

```json
{
  "error": {
    "code": "INVALID_IMAGE",
    "message": "The uploaded file is not a supported image."
  }
}
```

## Error contract

| Situation | HTTP | Code |
|---|---:|---|
| Missing multipart `file` | 400 | `MISSING_FILE` |
| Non-image file | 400 | `INVALID_IMAGE` |
| Corrupt/undecodable image | 400 | `INVALID_IMAGE` |
| Image below minimum dimensions | 400 | `INVALID_IMAGE` |
| Empty upload | 400 | `INVALID_IMAGE` |
| Upload exceeds 10 MiB | 413 | `FILE_TOO_LARGE` |
| Model cannot be loaded at startup | 503-equivalent startup failure | `MODEL_UNAVAILABLE` |
| Gallery cannot be loaded at startup | 503-equivalent startup failure | `GALLERY_UNAVAILABLE` |
| Valid request produces no products | 404 | `NO_RESULTS` |
| Unexpected server failure | 500 | `INTERNAL_ERROR` |

`k` validation remains FastAPI's normal 422 validation because it is a request-parameter contract error, not an image/runtime failure.

## Responsibility boundaries

- S4.2 performs byte/image validation and preprocessing and now raises typed preprocessing errors.
- S4.6 translates those typed failures into the public API contract.
- S4.3 remains responsible for gallery artifact validation.
- `scripts/run_api.py` translates model/gallery loading failures into explicit startup failures.
- S4.1 continues to propagate inference exceptions instead of owning HTTP concerns.

## Security behavior

Unexpected exceptions are converted to `INTERNAL_ERROR`; exception text, filesystem paths, checkpoint details, and stack traces are not returned to clients.

## Important distinction

Model and gallery artifacts are loaded before the Uvicorn server starts by the current MVP launcher. Therefore their unavailable state is reported as a clear startup failure rather than as a request-time HTTP 503. The API layer also supports explicit `MODEL_UNAVAILABLE` and `GALLERY_UNAVAILABLE` exceptions for runtime integrations.
