# S4.1 — Inference Pipeline

## Objective

Compose the existing model and retrieval components into one deterministic runtime inference path for the functional MVP.

## Scope

S4.1 owns orchestration only. It does not implement raw-upload validation, query preprocessing, gallery filesystem loading, HTTP/API transport, response serialization, or error translation. Those responsibilities remain in S4.2–S4.6.

## Pipeline

```text
Preprocessed query tensor [3, 224, 224]
        ↓
EmbeddingExtractor.extract_one()
        ↓
query embedding [128]
        ↓
SimilaritySearchEngine.search()
        ↓
ProductSearchResult
        ↓
ProductRanker.rank()
        ↓
RankedProductSearchResult
        ↓
SimilarityScoreConverter.score()
        ↓
ScoredProductSearchResult
```

The pipeline reuses the S3.8/S3.9/S3.10 contracts without duplicating their logic.

## Input contract

- Preprocessed PyTorch tensor for one query image.
- Expected project preprocessing is RGB → resize to `224 × 224` → float32 CHW → ImageNet normalization.
- Query preprocessing itself is implemented by S4.2.

## Output contract

S4.1 returns the existing `ScoredProductSearchResult`, containing:

- `query_id`
- ranked unique product candidates
- `product_id`
- category
- raw cosine similarity
- display `Similarity Score` in `[0, 100]`
- matched image IDs and paths
- one-based rank

The Similarity Score remains a display metric, not a probability.

## Dependency boundaries

Dependencies are injected into `InferencePipeline`:

- embedding extractor: existing `EmbeddingExtractor` contract
- search engine: existing S3.8 `SimilaritySearchEngine`
- ranker: existing S3.9 `ProductRanker`
- score converter: existing S3.10 `SimilarityScoreConverter`

This keeps checkpoint paths and gallery paths outside S4.1 and allows S4.2/S4.3 to construct them later.

## Error policy

S4.1 intentionally does not catch or translate exceptions. Existing component errors propagate to S4.6, where the functional API layer will define user-facing error handling.

## Tests

`tests/inference/test_pipeline.py` covers:

- complete orchestration from embedding to scored results
- query ID and K propagation
- self-image exclusion propagation
- default dependency construction
- dependency injection
- empty search result propagation
