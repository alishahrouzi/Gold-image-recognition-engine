# S3.8 — Similarity Search Engine

## Objective

Implement the product-level similarity-search stage for the metric-learning retrieval pipeline without changing the existing S2.7 baseline retrieval implementation.

## Contract

```text
query_embedding
      ↓
image-level cosine similarity against gallery
      ↓
optional self-image exclusion
      ↓
group matching gallery images by product
      ↓
strongest image match = raw product similarity evidence
      ↓
unique Top-K product candidates
```

The S3.8 API is `SimilaritySearchEngine.search()`.

### Input

- One query embedding with shape `[D]` or `[1, D]`.
- A materialized image-level gallery (`[N, D]`) and aligned metadata.
- `k >= 1`.
- Optional `exclude_image_id` for leave-one-out/search scenarios.

### Output

`ProductSearchResult` containing up to `k` unique `ProductSearchCandidate` objects.

Each product candidate contains:

- `product_id`
- `category`
- raw `similarity`
- all matched gallery `image_id` values for that product
- corresponding image paths when available

The S3.8 result intentionally has **no rank field and no required output ordering**. It returns the selected Top-K product candidate set; explicit `Similarity ↓` ordering is S3.9's responsibility.

## Product aggregation policy

The gallery is intentionally image-level, as established in S3.7. A product may therefore have multiple gallery images. S3.8 groups those image matches by `product_id` and uses the maximum image-level cosine similarity as the product's raw search similarity.

This is deliberately a simple, deterministic MVP aggregation rule. It does **not** introduce a learned aggregation model.

## Separation from later Sprint 3 tasks

S3.8 owns search and product candidate generation.

- **S3.9 — Ranking:** owns the explicit reusable product ordering stage (`Similarity ↓`).
- **S3.10 — Similarity Score:** converts raw similarity/distance into the displayable **Similarity Score**. It is not a probability.
- **S3.11 — Retrieval Evaluation:** owns Top-1/5/10, Precision@K, Recall@K and MRR evaluation.
- **S3.12 — Compare Baseline vs Metric Learning:** owns final model comparison.

S3.8 does not add any display-score conversion, evaluation, training, or baseline-vs-Siamese comparison.

## Compatibility

The new engine accepts the canonical S3.7 metadata (`product_id`, `category`, `image`) and also accepts the legacy S2.7 product identity fields (`product_group`) so the existing gallery/retrieval artifacts remain usable.

The existing `TopKRetriever`, `RetrievalResult`, and `BaselineRetrievalPipeline` were not modified. They remain the S2.7 baseline path.

## Validation

The S3.8 tests cover:

- `[D]` and `[1, D]` query shapes
- embedding dimension mismatch
- non-finite query values
- invalid `k`
- unique product grouping
- multiple images belonging to one product
- strongest-match product similarity
- self-image exclusion
- legacy `product_group` metadata compatibility
- grouping an existing S2.7 `RetrievalCandidate` sequence
- deterministic product selection and bounded Top-K output

Policy identifier: `s3.8-product-similarity-search-v1`.
