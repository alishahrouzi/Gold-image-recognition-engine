# S4.9 — Human Visual-Relevance Evaluation

## Purpose

S4.9 automatic evaluation establishes category-aware retrieval quality, but category correctness is not equivalent to visual similarity. The S4.9 protocol therefore retains ranked Top-10 candidates as the evidence set for human visual-relevance annotation.

This stage uses the frozen s3.5_cross_category runtime and does not retrain or change the model.

## Annotation set

The default package samples 20 validation queries per category using deterministic random sampling with seed 42:

- Bracelet: 20
- Earrings: 20
- Necklace: 20
- Pendant: 20
- Ring: 20
- Total: 100 queries
- Judgments: 1,000 (Top-10 per query)

The validation split is used for development/error analysis. The untouched test split remains reserved for final confirmation and must not be used to tune the model.

## Relevance rubric

| Label | Meaning |
|---|---|
| 0 | Irrelevant |
| 1 | Weakly similar |
| 2 | Visually similar |
| 3 | Highly similar |

For binary retrieval metrics, labels 2 and 3 count as relevant.

Judge visual appearance rather than category alone. Candidate category and similarity are hidden in the annotation UI.

The representative candidate image is the gallery image with the strongest image-level match for that product, which is the first entry in the persisted matched-image list.

## Generation

From the repository root:

    python scripts/run_s4_9_human_relevance.py --dataset-root "PATH_TO_DATASET1"

Or set ZARGAR_DATASET1_ROOT and run:

    python scripts/run_s4_9_human_relevance.py

The script reads:

- experiments/final_evaluation/s4.9/s3.5_cross_category/valid_evaluation.json
- reports/dataset/dataset1_manifest.csv

and writes a local annotation package under:

experiments/final_evaluation/s4.9/human_relevance/

including:

- annotation_manifest.json
- annotation_template.csv
- annotation.html

The HTML interface stores progress in browser local storage and exports the completed CSV. Generated local annotation assets should not be committed to Git because they depend on the user's local Dataset 1 paths.

## Integrity rules

1. Do not regenerate the S4.9 retrieval outputs while annotating.
2. Do not change the selected model.
3. Keep the query set and seed fixed once annotation starts.
4. Use the resulting labels for visual-search quality analysis and error analysis, not for changing the original S4.9 model-selection decision.

## Next step

After the CSV is completed, a separate evaluator should calculate human-relevance metrics and produce the S4.9 visual-relevance report. Those results then feed S4.9 error analysis and Sprint 5 optimization decisions.
