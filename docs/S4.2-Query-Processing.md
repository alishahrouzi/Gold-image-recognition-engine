# S4.2 — Query Processing

## Objective

Convert one uploaded query image into the deterministic tensor contract consumed by S4.1.

## Runtime flow

```text
Upload
  ↓
Source validation
  ↓
Image decode
  ↓
Dimension validation
  ↓
RGB conversion
  ↓
Resize 224×224
  ↓
Float32 CHW [0,1]
  ↓
ImageNet normalization
  ↓
Finite tensor [3,224,224]
  ↓
S4.1 InferencePipeline
```

## Scope

S4.2 owns transport-independent query input validation and preprocessing. It does not implement model loading, embedding extraction, gallery loading, similarity search, ranking, scoring, HTTP routing, or UI concerns.

## Accepted sources

`QueryProcessor.process()` accepts:

- raw `bytes`
- `bytearray`
- `memoryview`
- an in-memory `PIL.Image.Image`
- a filesystem path (`str` or `Path`)

The API layer in S4.4 can read an uploaded file and pass its bytes without coupling this module to FastAPI.

## Validation

Default upload limit: 10 MiB.

Default minimum image dimensions: `32 × 32` pixels.

Empty payloads, oversized payloads, undecodable image bytes, unsupported source types, and images below the minimum dimensions raise `PreprocessingError`.

## Image handling

RGB conversion reuses the existing ingestion behavior. Grayscale images become RGB; RGBA/transparent images are composited onto a white RGB background. Original files are never modified.

The existing deterministic `ImagePreprocessor` remains the single source of truth for resize, tensor conversion, ImageNet normalization, shape, dtype, and finite-value validation.

## Output

`ProcessedQuery` contains:

- `tensor`: `[3, 224, 224]`, `float32`, normalized and finite
- `original_size`
- `original_mode`
- decoded image format when available
- uploaded source byte count when the source was raw bytes

`process_tensor()` is a convenience method returning only the tensor.

## Boundary with S4.1

S4.2 produces the exact input expected by `InferencePipeline.run()`:

```text
ProcessedQuery.tensor
        ↓
InferencePipeline.run()
        ↓
Embedding → Search → Ranking → Similarity Score
```

Policy: `s4.2-query-processing-v1`
