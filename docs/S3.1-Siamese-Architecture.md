# S3.1 — Siamese Architecture

## Purpose

S3.1 introduces the shared-backbone Siamese architecture required for metric learning. It changes the model interface from a single-image embedding path to a two-image relationship-learning interface without introducing a training loss or pair-sampling policy.

## Architecture

```text
                 ┌──────────────────────────────┐
Image A ────────►│                              │────► Embedding A [B, 128]
                 │  Shared EncoderWithEmbedding │
Image B ────────►│       Head / Backbone         │────► Embedding B [B, 128]
                 │                              │
                 └──────────────────────────────┘
```

Both inputs are passed through the same `EncoderWithEmbeddingHead` instance. Therefore, the CNN encoder and embedding projection have one shared set of parameters.

## Reused S2 components

- `CustomCNNEncoder`: from-scratch CNN, default raw feature width 256.
- `EmbeddingHead`: Linear `256 → 128` followed by L2 normalization.
- `EncoderWithEmbeddingHead`: existing composition of the encoder and embedding head.

No second CNN, duplicated weights, or new representation architecture is introduced.

## Public contract

```python
model = SiameseNetwork()
embedding_a, embedding_b = model(image_a, image_b)
```

Inputs:

- `image_a`: `[B, 3, 224, 224]`
- `image_b`: `[B, 3, 224, 224]`

Default outputs:

- `embedding_a`: `[B, 128]`
- `embedding_b`: `[B, 128]`
- each embedding is L2-normalized.

A single-image `encode(images)` helper is also provided for reuse of the shared embedding path.

## Explicit scope boundary

S3.1 does **not** implement:

- Contrastive Loss
- Triplet Loss
- pair/triplet dataset construction
- positive/negative sampling
- hard-negative mining
- augmentation policy
- retrieval changes
- FAISS/ANN indexing
- test-set evaluation

Those concerns remain separate so that the architecture can support multiple metric-learning objectives in later S3 tasks.

## Validation

The S3.1 test suite verifies:

- default 128-D embedding contract
- batch sizes 1, 4, and 16
- finite outputs and unit L2 norms
- shared encoder/head instance
- deterministic identical-input behavior in evaluation mode
- equivalence between Siamese paths and direct shared-backbone calls
- gradient flow through both paths
- custom encoder/head injection
- invalid input rejection
- CPU execution
- CUDA execution when available
