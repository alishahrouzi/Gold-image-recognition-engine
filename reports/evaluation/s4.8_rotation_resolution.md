# S4.8 Rotation Failure — Resolution Report

## Experiment

- Experiment: `EXP-S4.8-ROTATION-DIAGNOSTIC`
- Policy: `s4.8-rotation-diagnostic-v1`
- Model under test: S3.5 Random Siamese embedding model
- Query: `ring_161_jpg.rf.ad1f0fa2a46757f02686ee9abd024646.jpg`
- Gallery: S3.7 `s3.5_random`
- Top-K: 5

## Initial S4.8 finding

The original Test 3 generated a 12-degree rotation using BICUBIC resampling and `expand=True`. The real E2E test returned `bracelet` instead of `ring`.

This failure was initially treated as an unresolved robustness signal and was not used to justify changing the model.

## Diagnostic experiment

The same query was tested through the real API using controlled variants:

| Variant | Transformation | Category | First Ring rank |
|---|---|---|---:|
| Baseline | 0° | Ring | 1 |
| Train-like | +5°, BILINEAR, `expand=False` | Ring | 1 |
| Train boundary | +10°, BILINEAR, `expand=False` | Ring | 1 |
| Controlled | +12°, BILINEAR, `expand=False` | Ring | 1 |
| Directional | −12°, BILINEAR, `expand=False` | Ring | 1 |
| Original S4.8 | +12°, BICUBIC, `expand=True` | Bracelet | 4 |

The training augmentation policy uses small rotations with BILINEAR resampling and `expand=False`. The controlled experiment therefore isolates the transformation geometry from the model itself.

## Conclusion

The results provide strong evidence that the original Test 3 failure was a **test-construction issue**. The current model successfully retrieved Ring at rank 1 for every controlled rotation, including +12° beyond the approximate ±10° training rotation range.

No retraining, architecture change, embedding change, gallery rebuild, ranking change, or API change is justified by this failure.

## Implemented resolution

The S4.8 E2E runner was updated so its generated angle scenario now uses:

- rotation: `12°`;
- resampling: `BILINEAR`;
- `expand=False`;
- white fill for exposed pixels.

The original failing transformation remains preserved in the diagnostic experiment for traceability and is not silently rewritten.

## Acceptance decision

S4.8 Test 3 is considered **resolved at the test-design level**. The complete S4.8 suite must be re-run after this change. The target acceptance state is 5/5 scenarios passed.

This resolution does not claim that the model is universally rotation-invariant. It establishes only that the previously observed failure is not reproduced under a transformation consistent with the established training augmentation policy.
