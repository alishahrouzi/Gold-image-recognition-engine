# S3.11 — Retrieval Evaluation

## Objective

Evaluate the actual **product-level metric-learning retrieval pipeline** produced by S3.8 and S3.9 using the official Sprint 3 retrieval metrics.

S3.11 is evaluation-only. It does not train models, change galleries, change ranking, or compare the Siamese result against the S2.7 baseline. Model comparison belongs to S3.12.

## Pipeline under evaluation

```text
S3.7 persisted image-level gallery
        ↓
query embedding (leave-one-image-out)
        ↓
S3.8 SimilaritySearchEngine
        ↓
unique product candidates
        ↓
S3.9 ProductRanker
        ↓
ranked products
        ↓
S3.11 metrics
```

S3.10 Similarity Score is deliberately not used for evaluation. Retrieval metrics must operate on the raw retrieval ranking, not a display conversion.

## Evaluation protocol

Each image in the train gallery is used once as a query against the same gallery with that exact image excluded.

The query's product remains relevant only when another image of the same product exists in the gallery. Therefore:

- singleton products cannot be evaluated for product retrieval and are excluded from aggregate metrics;
- product identity is the ground truth;
- category is not used to decide whether a result is correct;
- other products in the same category remain negatives;
- each valid query has exactly one relevant product identity.

Dataset 1's S3.7 train gallery contains 4328 images across 1494 products. Based on the established group structure, 4314 query images have another image from the same product in the gallery; 14 query images are excluded because their product has no second gallery image.

## Metrics

### Top-1 / Top-5 / Top-10

For each valid query, the metric is 1 when the query's true product appears within the first K ranked products and 0 otherwise. The reported value is the mean across valid queries.

### Precision@K

```text
Precision@K = relevant retrieved products / K
```

There is exactly one relevant product per valid query in this product-identity protocol. Thus a successful hit contributes `1/K` to Precision@K.

### Recall@K

```text
Recall@K = relevant retrieved products / total relevant products
```

Because there is exactly one relevant product, Recall@K is equivalent to the Top-K hit indicator for each query.

### MRR

```text
MRR = mean(1 / rank_of_first_relevant_product)
```

A query whose true product is outside the evaluated Top-10 ranking contributes zero.

## Models evaluated

The CLI can evaluate the four persisted S3.4/S3.5 metric-learning galleries independently:

- `s3.4_hybrid`
- `s3.5_random`
- `s3.5_same_category`
- `s3.5_cross_category`

Evaluating all four here provides retrieval evidence for the S3.5 sampling-strategy experiments without changing the official task boundary. It does not perform the baseline-vs-Siamese comparison.

## Output

Default JSON:

```text
reports/evaluation/s3.11_retrieval_evaluation.json
```

Default Markdown:

```text
reports/evaluation/s3.11_retrieval_evaluation.md
```

The report contains aggregate metrics, query counts, diagnostics, per-category metrics, gallery consistency checks, and the exact evaluation policy.

## Responsibilities

### S3.11 owns

- retrieval evaluation
- Top-1
- Top-5
- Top-10
- Precision@K
- Recall@K
- MRR
- per-category retrieval metrics
- leave-one-image-out evaluation diagnostics

### S3.11 does not own

- model training
- gallery construction
- similarity search
- ranking
- display score conversion
- baseline-vs-metric-learning comparison

Those responsibilities remain in S3.4/S3.7, S3.8, S3.9, S3.10 and S3.12 respectively.

Policy identifier: `s3.11-product-retrieval-evaluation-v1`.
