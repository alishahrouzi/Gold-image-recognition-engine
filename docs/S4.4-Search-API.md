# S4.4 — Search API

## Objective

Expose the functional MVP retrieval pipeline through a thin HTTP API.

## Endpoint

```text
POST /search
Content-Type: multipart/form-data

file=<query image>
k=<optional Top-K, default 5, range 1..50>
```

The endpoint accepts one uploaded image and forwards it through the existing
S4.2 → S4.1 runtime path. No retrieval logic is implemented in the HTTP layer.

## Runtime flow

```text
HTTP multipart upload
        ↓
POST /search
        ↓
UploadFile.read()
        ↓
QueryProcessor.process()
        ↓
ProcessedQuery.tensor
        ↓
InferencePipeline.run(k)
        ↓
Embedding → Search → Ranking → Similarity Score
        ↓
JSON serialization of ScoredProductSearchResult
```

S4.2 remains responsible for image validation and deterministic preprocessing.
S4.1 remains responsible for inference orchestration. S3.8, S3.9 and S3.10
remain responsible for product search, ranking and display-score conversion.

## Dependency boundary

`SearchService` receives `QueryProcessor` and `InferencePipeline` through
constructor injection. The API module therefore does not create a model or
load a gallery at import time.

The local runtime runner (`scripts/run_api.py`) explicitly loads:

- the selected S3.5 Siamese checkpoint;
- the selected S3.7 gallery (`s3.5_random` by default);
- the S4.2 query processor;
- the S4.1 inference pipeline.

This keeps model/checkpoint lifecycle outside the HTTP route itself.

## Current MVP defaults

- model: `s3.5_random`
- embedding dimension: `128`
- similarity metric: cosine similarity
- default Top-K: `5`
- API Top-K bounds: `1..50`
- default query maximum upload size: `10 MiB`
- default query minimum dimensions: `32 × 32`

## Response boundary

S4.4 currently serializes the existing `ScoredProductSearchResult` contract
using FastAPI's JSON encoder. A stable public response schema, field naming,
metadata selection and API-facing response model belong to S4.5.

## Error boundary

S4.4 intentionally does not translate domain exceptions into user-facing API
errors. `PreprocessingError`, model errors, gallery errors and retrieval errors
are allowed to propagate until S4.6 defines the API error contract.

## Local execution

Install the added API dependencies and run:

```bash
pip install -r requirements.txt
python scripts/run_api.py --checkpoint <path-to-s3.5-random-checkpoint>
```

The default server listens on `127.0.0.1:8000`.

The interactive API documentation is then available through FastAPI's standard
OpenAPI/Swagger UI at `/docs`.

## Tests

`tests/api/test_search_api.py` verifies:

- `/health` liveness endpoint;
- multipart image upload to `/search`;
- S4.2 preprocessing before S4.1 invocation;
- default `k=5` propagation;
- custom `k` propagation;
- HTTP rejection of invalid `k`.

Policy: `s4.4-search-api-v1`
