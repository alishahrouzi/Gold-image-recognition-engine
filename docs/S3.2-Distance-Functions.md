# S3.2 — Distance Functions

## Purpose

S3.2 provides reusable distance functions for metric-learning embeddings without changing the S3.1 Siamese architecture or the S2.7 baseline retrieval implementation.

## Contract

All distances are lower-is-better and support two modes:

- Pairwise: `[B, D]` + `[B, D]` → `[B]`
- Matrix: `[Q, D]` + `[G, D]` → `[Q, G]`

The pairwise API is exposed through `DistanceFunction.__call__`.

## Implementations

### Cosine Distance

`1 - cosine_similarity`

Inputs are L2-normalized defensively before the dot product. This matches the project's normalized embedding space while keeping the primitive correct when called independently.

### Euclidean Distance

Standard L2 distance:

`||x - y||_2`

The matrix implementation uses the expanded squared-distance identity and clamps the squared result at zero before the square root for numerical stability.

## Relationship in the current embedding space

The project's embedding head L2-normalizes embeddings. For unit vectors:

`D_euclidean^2 = 2 * D_cosine`

Therefore the two metrics produce equivalent rankings for the current normalized embedding space, although their numeric distance scales differ.

## Scope boundaries

This task does not modify:

- `SiameseNetwork`
- Contrastive/Triplet losses
- Pair sampling
- Training
- Augmentation
- FAISS/ANN retrieval
- S2.7 `TopKRetriever`
- S2.8/S2.9 evaluation results

The existing retrieval cosine-similarity primitive remains the S2.7 baseline path. S3.2 is an independent metric-learning distance layer for later S3 tasks.
