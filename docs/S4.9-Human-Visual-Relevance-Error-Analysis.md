# S4.9 — Human Visual-Relevance Error Analysis

This step analyzes the completed S4.9 human annotations for the frozen
`s3.5_cross_category` model. It is validation/development analysis only and
does not retrain or modify the model.

## What is measured

The analysis uses the existing 0–3 relevance labels and classifies each query
by where the first relevant result (relevance >= 2) appears:

- `no_relevant_in_top10`: no relevant result in Top-10.
- `relevant_in_top5_but_not_top1`: a relevant result exists in Top-5, but not at rank 1.
- `relevant_only_in_ranks_6_to_10`: a relevant result exists only below Top-5.
- `relevant_at_top1_only_or_sparse`: Top-1 is relevant, with sparse additional Top-5 relevance.
- `relevant_at_top1_with_additional_top5_relevance`: Top-1 is relevant and at least one additional relevant result is in Top-5.

These are **ranking failure modes**, not inferred visual root causes. Angle,
lighting, crop/background, viewpoint, and fine-grained design causes require
manual inspection of the corresponding query/candidate images.

## Run

After the completed annotation CSV exists:

    python scripts/analyze_s4_9_human_relevance.py

Output:

    experiments/final_evaluation/s4.9/human_relevance/s4.9_error_analysis.json

The output includes overall and per-category counts, first-relevant rank
statistics, relevance-label distribution, and every annotated query's failure
classification.

## Integrity rules

- Model remains frozen at `s3.5_cross_category`.
- Source split remains `valid`.
- Test labels are not read or used.
- No tuning decision is made by this script.
- The report must not be presented as a causal diagnosis without image-level
  inspection.
