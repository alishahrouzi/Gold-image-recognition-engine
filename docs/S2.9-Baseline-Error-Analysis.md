# S2.9 — Baseline Error Analysis

## Objective

S2.9 analyzes the first retrieval baseline from S2.8 without changing the
model, retrieval pipeline, dataset manifest, or evaluation protocol.

The goal is to identify reproducible retrieval failure patterns and produce
auditable evidence for visual inspection before S3.

## Source experiment

- Source experiment: `EXP-0002`
- Task: `S2.9`
- Policy: `s2.9-baseline-error-analysis-v2`
- Dataset: Dataset 1
- Query split: `train`
- Gallery split: `train`
- Protocol: leave-one-image-out
- Similarity: cosine
- K: 10
- Self-image exclusion: existing S2.7 `TopKRetriever`
- Positive definition: `candidate.product_group == query.product_group`
- Test split: **not used**

## Automated evidence

For each query the analysis retains:

- query image path
- query category
- query product group
- first positive rank
- Top-1 / Top-5 / Top-10 correctness
- Top-1, Top-5 and Top-10 image candidate metadata
- products represented in the observed Top-10 image candidates
- Top-1 similarity
- best observed similarity for the query product
- Top-1-to-positive similarity margin when a positive is observed

The product evidence is intentionally **not** called a Top-10 product retrieval:
the S2.7 retriever returns ten images, and the analysis collapses those image
results to first-seen product groups only for explanation.

## Category analysis

The report produces deterministic per-category statistics and Top-1 retrieval
category confusion. It also adds category-stratified samples so a large
category such as Necklace does not dominate or disappear from the manual review
set.

The category-stratified samples use a deterministic seed and a configurable
`--per-category` value (default: 3).

## Representative error groups

The runner selects deterministic examples for:

1. Top-1 correct
2. Top-1 wrong / Top-5 correct
3. Top-5 wrong / Top-10 correct
4. Top-10 wrong
5. No positive in Top-10
6. Highest-similarity incorrect Top-1 matches
7. Lowest-similarity correct Top-1 matches
8. Smallest observed Top-1-to-positive similarity margins among incorrect queries
9. Category-stratified Top-10 failures
10. Category-stratified high-similarity Top-1 failures

Default general sample size is 10 per group; default category-stratified sample
size is 3 per category; selection seed is 42.

## Interpretation of similarity margins

`top1_to_positive_similarity_margin` is defined only when the query product is
represented among the observed Top-10 image candidates. For an incorrect
query, a positive margin means the wrong Top-1 image is more similar than the
best observed image of the correct product.

Aggregate margin diagnostics are therefore restricted to incorrect queries
with an observed positive. Correct Top-1 queries are not mixed into the error
margin statistic.

## Visual analysis

Angle/viewpoint and background are deliberately **not** inferred from
similarity values, filenames, or category labels. The automated report marks
both dimensions as `manual_review_required` and provides the query/candidate
image paths needed for visual inspection.

Manual review should answer:

- Does the query show a materially different viewpoint from the positive?
- Does the query have a materially different background or presentation style?
- Is the retrieved wrong product visually similar despite being a different product group?
- Is the failure actually category confusion rather than viewpoint/background sensitivity?

Only observations supported by inspected images should be recorded as S2.9
findings or converted into S3 hypotheses.

## S2.8 baseline reference

The immutable baseline reference is:

| Metric | S2.8 |
| --- | ---: |
| Top-1 | 0.014140 |
| Top-5 | 0.043811 |
| Top-10 | 0.065137 |
| MRR | 0.027050 |

These values are baseline evidence, not a final test-set score.

## Limitations

- The automated stage cannot establish visual causes such as angle or background without image inspection or reliable annotations.
- Product evidence is derived from the existing Top-10 image ranking and is not a separate product-level retrieval run.
- The S2.9 report is an error-analysis artifact, not a new model baseline.
- The test split remains reserved for final evaluation.

## S3 hand-off

S2.9 should produce hypotheses, not model changes. Any proposed change to
augmentation, embedding learning, loss functions, sampling, or architecture
belongs to the S3 experiment design and must be evaluated under a new
experiment ID.
