# S4.6 — Error Handling

Stable public error boundary for the MVP search API. Internal model, gallery, preprocessing, and runtime exceptions must not leak implementation details.

## Public error schema

```json
{
  "error": {
    "code": "INVALID_IMAGE",
    "message": "The uploaded file is not a supported image."
  }
}
```

## Contract

| Situation | HTTP | Code |
|---|---:|---|
| Missing multipart `file` | 400 | `MISSING_FILE` |
| Non-image file | 400 | `INVALID_IMAGE` |
| Corrupt/undecodable image | 400 | `INVALID_IMAGE` |
| Image below minimum dimensions | 400 | `INVALID_IMAGE` |
| Empty upload | 400 | `INVALID_IMAGE` |
| Upload exceeds 10 MiB | 413 | `FILE_TOO_LARGE` |
| Model unavailable during startup | startup failure | `MODEL_UNAVAILABLE` |
| Gallery unavailable during startup | startup failure | `GALLERY_UNAVAILABLE` |
| Valid request produces no products | 404 | `NO_RESULTS` |
| Unexpected server failure | 500 | `INTERNAL_ERROR` |

`k` remains normal FastAPI 422 validation.

## Boundaries

S4.2 owns image validation/preprocessing; S4.3 owns gallery artifact validation; S4.6 owns public exception translation; the launcher reports startup dependency failures; S4.1 remains HTTP-independent.

Unexpected exceptions are sanitized to `INTERNAL_ERROR` without exposing paths, checkpoint details, or stack traces.
