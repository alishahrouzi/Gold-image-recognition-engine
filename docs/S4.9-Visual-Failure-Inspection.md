# S4.9 — Image-Level Visual Failure Inspection

## Purpose

This stage investigates **observed visual failure patterns** after human
relevance evaluation. It does not infer angle, lighting, crop, or design
causes from metrics. A human inspects the query and all ten retrieved
candidates and records an observed primary cause, optional secondary causes,
and evidence notes.

## Frozen evaluation contract

- Model: `s3.5_cross_category`
- Source split: `valid`
- Retrieval results: existing S4.9 results; no rerun
- Human relevance labels: existing completed 100-query annotation set
- Test labels: not used
- Training/model parameters: unchanged
- Selection seed: 42
- Default sample: 10 eligible failure/ranking-error queries per category (50 total)

The default selector excludes queries classified as
`relevant_at_top1_with_additional_top5_relevance`, because the purpose is
to inspect failures and sparse/ranking-error cases. It reuses the original
Top-10 judgments rather than asking for relevance again.

## Root-cause labels

The annotator may record:

- viewpoint / angle difference
- lighting / exposure / reflections
- crop / scale / framing
- background / scene context
- pose / composition / placement
- fine-grained design mismatch
- category looks similar but design is different
- no sufficiently similar gallery item is visible
- no obvious visual cause

These are **manual observations**, not automatic diagnoses. Multiple labels
are allowed, but one primary label is required.

## Run

From the repository root:

```bash
python scripts/run_s4_9_visual_failure_inspection.py --dataset-root "PATH_TO_DATASET1"
```

The script reads:

- `experiments/final_evaluation/s4.9/human_relevance/s4.9_human_relevance_annotations.csv`
- `experiments/final_evaluation/s4.9/human_relevance/s4.9_error_analysis.json`

and creates local, dataset-dependent assets under:

`experiments/final_evaluation/s4.9/human_relevance/visual_failure_inspection/`

Open `inspection.html` in a browser, inspect each query against all Top-10
candidates, and export:

`s4.9_visual_failure_inspection.csv`

The local HTML and exported CSV contain machine-local image paths and should
not be committed.

## Interpretation rule

Do not convert a frequent root-cause label directly into a model change.
After annotation, aggregate the observations by category and failure class.
Only then use the resulting evidence to prioritize Sprint 5 experiments such
as augmentation, sampling/mining, embedding/loss changes, or retrieval
changes.

The purpose of this stage is to establish **what the failures look like**,
not to decide their remedy in advance.
