# S4.8 — End-to-End Testing

S4.8 validates the complete MVP runtime path with real image files against the running API:

`Image → HTTP /search → QueryProcessor → InferencePipeline → Gallery Search → Ranking → Similarity Score → SearchResponse`

## Scenarios

| Test | Scenario | Expected behavior |
|---|---|---|
| 1 | Ring image → similar rings | HTTP 200, non-empty unique results, category `ring` |
| 2 | Necklace image → similar necklaces | HTTP 200, non-empty unique results, category `necklace` |
| 3 | Same ring under a different angle | HTTP 200, non-empty results, category remains `ring` |
| 4 | Same ring under different lighting | HTTP 200, non-empty results, category remains `ring` |
| 5 | Query image whose product is absent from the runtime Gallery | HTTP 200 with nearest Gallery products; no OOD rejection is expected in the current MVP |

## Test data policy

Tests 1 and 2 default to Dataset 1 `test/` images. This keeps the query images outside the S3.7 train Gallery and avoids trivial exact-gallery-image retrieval.

Tests 3 and 4 accept real manually selected images through CLI arguments. If omitted, the runner creates controlled robustness variants from the ring test image. Test 3 uses a **12-degree BILINEAR rotation with `expand=False`**, matching the geometry/resampling policy used by training augmentation. Test 4 uses reduced brightness and increased contrast.

## Rotation diagnostic

The original S4.8 rotation failure used BICUBIC + `expand=True`. A controlled diagnostic showed that training-like +5°, +10°, +12° and -12° BILINEAR/`expand=False` variants retained Ring at rank 1, while the original test construction produced Bracelet at rank 1. The runner was therefore corrected without retraining.

The report is stored in `experiments/e2e/s4.8_rotation_diagnostic.json`.

## Test 5 and OOD limitation

The current retrieval system does not implement an OOD detector or calibrated
rejection threshold. An out-of-gallery product therefore receives the nearest
available gallery products. Test 5 validates graceful retrieval behavior; it
does not prove product absence.

## Execution

Start the real MVP API with the **S4.9-selected** checkpoint:

```bash
python scripts/run_api.py --checkpoint <path-to-s3.5-cross-category-checkpoint>
```

Then:

```bash
python scripts/run_e2e_tests.py
```

For explicit images:

```bash
python scripts/run_e2e_tests.py \
  --ring-image <ring-test-image> \
  --necklace-image <necklace-test-image> \
  --angle-image <real-angle-image> \
  --light-image <real-lighting-image> \
  --out-of-gallery-image <external-image>
```

The report is written to `experiments/e2e/s4.8_e2e_report.json`.

## Acceptance

The acceptance state for S4.8 is 5/5 scenarios passed. S4.8 is runtime/integration
validation, not a replacement for S4.9 quantitative retrieval evaluation.
