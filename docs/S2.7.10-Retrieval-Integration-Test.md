# S2.7.10 — Retrieval Integration Test

## Objective

Verify the complete baseline retrieval path as a single unit:

```text
Query Image
    ↓
EmbeddingExtractor
    ↓
Query Embedding
    ↓
TopKRetriever
    ↓
RetrievalResult
```

The test intentionally uses a deterministic dummy embedding model and an in-memory gallery. It does not require the real Dataset 1 files, GPU, or a checkpoint.

## Covered contracts

- Query image is accepted by `BaselineRetrievalPipeline`.
- `EmbeddingExtractor.extract_one()` produces the query embedding.
- Gallery embeddings are passed to `TopKRetriever`.
- Candidates are ranked by descending cosine similarity.
- `RetrievalResult.query_id` is preserved.
- Candidate ranks are assigned correctly.
- `k` limits the result count.
- `exclude_image_id` propagates through the pipeline and removes a self-match.

## Scope boundary

This is an integration/contract test, not retrieval quality evaluation. It does not report Recall@K or other product-level retrieval metrics because the S2.7 baseline gallery/validation protocol has no cross-split product-group overlap.

## Definition of Done

- `tests/retrieval/test_pipeline.py` exists.
- End-to-end pipeline ranking is covered.
- Self-match exclusion is covered.
- Tests run without real model weights or dataset files.
- No changes to the production retrieval architecture are introduced.
