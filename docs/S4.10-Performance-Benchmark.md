# S4.10 — MVP Performance Benchmark

S4.10 measures the warm runtime path of the actual MVP API:

`image upload → preprocessing → embedding → gallery search → ranking → score → JSON response`.

It is intentionally separate from training benchmarks and does not modify the
model or gallery.

## Protocol

- Start the selected MVP API with `s3.5_cross_category`.
- Use representative images outside the runtime train gallery when possible.
- Warm up each image before measurement.
- Record sequential HTTP latency.
- Report mean, P50, P95, P99, min/max, error rate and sequential requests/sec.
- Record the exact query-image paths and environment.
- Cold-start/model-loading time is not included in warm request latency.

Default benchmark: 2 warmups + 10 measured requests per supplied image.

## Run

Start the API:

```bash
python scripts/run_api.py --checkpoint <path-to-s3.5-cross-category-checkpoint>
```

Then:

```bash
python scripts/benchmark_s4_10_mvp.py \
  --image <ring-image> \
  --image <necklace-image> \
  --image <earring-image>
```

The machine-readable report is written to
`experiments/benchmark/s4.10_mvp_performance.json`.

For the employer demo, report the measured numbers from the same machine/API
configuration rather than quoting an unexecuted target.

## Interpretation

This benchmark is an engineering performance measurement. It does not
establish a production SLA because the MVP dataset, hardware, concurrency,
network path and company production environment can differ.
