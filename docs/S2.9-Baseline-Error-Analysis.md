# S2.9 — Baseline Error Analysis

## Objective

S2.9 analyzes the first retrieval baseline from S2.8 without changing the
model, retrieval pipeline, dataset manifest, or evaluation protocol.

The goal is to identify reproducible retrieval failure patterns and produce a
small deterministic set of examples for visual inspection before S3.

## Source experiment

- Source experiment: `EXP-0002`
- Task: `S2.9`
- Policy: `s2.9-baseline-error-analysis-v1`
- Dataset: Dataset 1
- Query split: `train`
- Gallery split: `train`
- Protocol: leave-one-image-out
- Similarity: cosine
- K: 10
- Self-image exclusion: existing S2.7 `TopKRetriever`
- Positive definition: `candidate.product_group == query.product_group`
- Test split: **not used**

## Why this is automated first

The train gallery contains thousands of query images. Reviewing all images by
hand would be slow, difficult to reproduce, and would not establish which
queries are representative of each failure mode.

The implementation therefore first computes per-query evidence using the
existing S2.7 retrieval result and S2.8 scoring contracts. It then selects a
small deterministic sample for manual inspection.

## Automated analysis

For each query the analysis retains:

- query image path
- query category
- query product group
- first positive rank
- Top-1 correctness
- Top-5 correctness
- Top-10 correctness
- Top-1 candidate metadata
- Top-5 candidate metadata
- Top-10 candidate metadata

It also produces:

- dataset summary
- per-category metrics
- incorrect Top-1 category confusion
- representative examples
- high-similarity incorrect examples
- low-similarity correct examples

The analysis does not rebuild embeddings and does not modify the S2.7 gallery.

## Representative error groups

The runner selects deterministic examples for:

1. Top-1 correct
2. Top-1 wrong / Top-5 correct
3. Top-5 wrong / Top-10 correct
4. Top-10 wrong
5. No positive in Top-10
6. Highest-similarity incorrect Top-1 matches
7. Lowest-similarity correct Top-1 matches

Default sample size is 10 per group and the selection seed is 42.

## Visual analysis

Angle/viewpoint and background are deliberately **not** inferred from
similarity values, filenames, or category labels. The automated report marks
both dimensions as `manual_review_required` and provides the query/candidate
image paths needed for visual inspection.

Manual review should answer:

- Does the query show a materially different viewpoint from the positive?
- Does the query have a materially different background or presentation style?
- Is the retrieved wrong product visually similar despite being a different product group?
- Is the failure actually category confusion rather than viewpoint/background sensitivity?

Only observations supported by inspected images should be recorded as S2.9
findings or converted into S3 hypotheses.

## S2.8 baseline reference

The immutable baseline reference is:

| Metric | S2.8 |
| --- | ---: |
| Top-1 | 0.014140 |
| Top-5 | 0.043811 |
| Top-10 | 0.065137 |
| MRR | 0.027050 |

These values are baseline evidence, not a final test-set score.

## Limitations

- The automated stage cannot establish visual causes such as angle or background without image inspection or reliable annotations.
- The S2.9 report is an error-analysis artifact, not a new model baseline.
- The test split remains reserved for final evaluation.

## S3 hand-off

S2.9 should produce hypotheses, not model changes. Any proposed change to
augmentation, embedding learning, loss functions, sampling, or architecture
belongs to the S3 experiment design and must be evaluated under a new
experiment ID.
